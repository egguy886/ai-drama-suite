# AI 短剧生产编排（工业升级增强版）

把创意变成一条可追溯的工业级生产链：导演判断 → 资产/声线 → 空间调度 → 镜头/光线/动作 → 不可变台词 → 提示词编译 → 实际画面 QC。

这是**控制合同层**，不重写既有导演或资产方法：

- 剧本解读、视觉概念、节拍/镜头归并、台词时序、剪辑动机与可生成性，按 `references/independent-production-core.md` 在本包内完成。
- 人物、场景、道具的真实外观、状态与审核，按本包内置资产合同完成。
- 角色声线、不可变台词与音频分轨隔离，按本包内置音频合同完成。
- 类型色彩、镜头偏好与材质参数，按本包内置类型适配表完成。

本 Skill 把这些已批准的决定变成本包内可传递、检查和回写的控制合同。

## 1. 先判断输入，补齐缺口

从用户输入提取：受众/时长、剧本形态、人物目标与阻力、场景、主类型、目标平台、已有关联资产、专属声线 WAV 或草图。缺失项写为 `pending`，不可用空泛的“爆款”“电影感”代填。大纲、草图或口述造成的补充事实必须写 `assumed`，不可伪装为原始设定。

| 输入状态 | 首要产物 | 本包处理层 |
|---|---|---|
| 只有故事点子 | `narrative_beat_contract` | 导演与剧本层 |
| 角色/场景尚未固定 | Cxx/Sxx/Pxx 资产合同 | 本包资产层 |
| 角色发声但音色易变 | `voice_anchor_contract` | 本包音频资产层 |
| 对白容易被 AI 篡改 | `immutable_dialogue_ledger` | 本包台词门禁层 |
| 已有资产，画面易漂移 | `blocking_map` | 本包镜头层 |
| 已有草图或分镜草稿 | `sketch_to_shot_brief` | 镜头与提示词层 |
| 对打、追逐、抢夺 | `action_ledger` | 镜头、提示词与成片检查层 |
| 画面“平”“假”“不高级” | `lighting_plan` | 镜头、提示词与成片检查层 |

## 2. 使用固定的生产顺序

1. 先按本包内置导演判断完成剧本三层读法、视觉概念与场策略；再从其判断结果写可检验的开场钩子、目标/阻力、策略或权力转折、结尾钩子。
2. 按本包内置资产合同建立 Cxx/Sxx/Pxx 与专属声线资产库（`voice_anchor_contract`）；先人工审核，再进入分镜。不要以视频抽卡替代资产库。
3. 锁定剧本不可变台词台账（`immutable_dialogue_ledger`），核算语速秒数并验证可见口型，严禁后续编译中擅自改写或删词。
4. 对每镜建立 `blocking_map`：空间锚点、人物位置/朝向/高度、道具位置、视线、摄影机和安全活动区必须能画在同一张平面图上。
5. 用本包类型适配层提供镜头、色彩和材质参数；类型参数不得改变审核过的资产外观。
6. 仅在需要时叠加专项合同：草图转镜头、布光、打戏动作账本。详细字段见 [control-contracts.md](references/control-contracts.md)。
7. 本包提示词编译层把所有合同装进既有六大模块外层与数字10信息内核：
   - 强制将配乐隔离为 `non_diegetic_music: SILENT`；
   - 现场物理动量与环境音效写入 `overall_soundscape`；
   - 角色出场发声严格绑定 `<Audio N>` ➔ `ref_audio_N`；
   - 逐字台词严格写入 `<d>[Language] ...</d>`。
8. 串行咬合接力：段 N 验收后，取结尾前 `0.35s` 稳定尾帧作为段 N+1 的 `<Picture 1>`。
9. 本包成片检查层用实际画面复核，不以平台任务成功、漂亮单帧或重复生成当作通过。

## 3. 九大约束性控制合同

### 3.1 剧本节拍合同
写 `hook / want / obstacle / strategy_shift / power_turn / cost / cliffhanger`，并记录观众信息差、人物进出状态差、情绪曲线与视觉概念引用。每项必须是画面或台词可观察的事实。

### 3.2 视觉资产库合同
资产库（`asset_registry`）是已批准 Cxx/Sxx/Pxx 的索引。每个条目至少有：`asset_id`、版本、状态、参考图、锁定特征、可变状态、来源镜头、最后审阅日期。版本变化使用后缀（如 `C01b`），绝不覆盖已批准版本。

### 3.3 声线锚定资产系统（Voice Anchor Binding）★
引入项目自建的 `VoxCPM2_EN/normalized/` 音频锁体系。当跟踪主角（如 Lucas、Elara、Kaiser、Grover 等）出场并有台词时，必须绑定实物标准 WAV 文件，并在提示词中指派专属标签（如 `<Audio 1>`），API 载荷中映射为 `ref_audio_0`。全剧角色音色绝对连续，严禁跨段漂移或依赖 AI 随机嗓音。

### 3.4 配乐静音隔离协议（non_diegetic_music: SILENT）★
为了保证分段视频后期剪辑的绝对连贯，**强制将视频生成模型的配乐参数设为 SILENT**。AI 视频模型仅负责生成现场物理音效与环境声（`overall_soundscape`：暴雨、踩脚、喘息、机甲轰鸣、碰撞），禁止生成背景音乐。背景配乐由剪辑师在剪辑台进行全局混音通铺，彻底杜绝切镜时的断崖式跳音刺耳。

### 3.5 不可变台词防篡改台账（Immutable Dialogue Ledger）★
锁定剧本原始台词，建立不可变台账。提示词中的对白必须与剧本原文 100% 逐字匹配，严格保留原始语言与标点，封装于 `<d>[Language] ...</d>` 中。严禁 AI 擅自扩写、润色、意译或删减剧本对白。画内说话必须保证说话人面部/嘴部在对应秒数内可见；若因镜头调度说话人背对或在画外，必须显式声明画外音（Off-Screen）。

### 3.6 场面调度图（blocking_map）
每张图固定：画面朝向、左中右/前中后空间锚、A/B 的位置和面向、道具初末位置、行动路径、进出画、遮挡物、摄影机位置/镜头方向、180°轴及权力几何。移动使用 `T0 → T1 → T2` 阶段。调度先于机位。

### 3.7 布光图（lighting_plan）
每镜列出主光、补光、轮廓/背景光的画内来源、方向、色温、强度或光比及照亮区域，并记录开镜/尾帧是否连续。

### 3.8 动作账本（action_ledger）
打戏与身体接触拆为可生成的交换单元：`起势 → 位移 → 接触/落空 → 反应 → 定格尾帧`。每个单元写清发力主体、清晰起点/路径/终点、受力反应与 **Anti-Bounce 刚体防回弹物理负向约束**。

### 3.9 草图转镜头（sketch_to_shot_brief）
草图只锁构图和关系，不直接锁人物脸或材质。必须由资产合同补齐外观与细节。

## 4. 提示词装配与协议编译

将所有合同信息编译为符合主流视频模型（MiniMax H3 / Kling 等）协议的标准结构：

```text
integrated_multimodal_description:
[Module 1: Production Task]: 时长、画幅、焦段、连续单镜头规则。
[Module 2: Primary Subjects]: 角色 (Cxx)、道具 (Pxx) 资产引用，绑定 <Picture N> 槽位，声线绑定 <Audio N>。
[Module 3: Scene World State]: 世界空间坐标、地标、实体光源方向与 180° 行动轴。
[Module 4: Dramatic Progression]: 剧情变化、权力转折与情绪推进。
[Module 5: Visual Style & Physical Discipline]: 光学特征、材质、重力、接触动量与 Anti-Bounce 物理禁令。
[Module 6: Kinematic Sequence]: 
- [00:00 - 00:XX]: 逐秒动作因果推进，触发式运镜，逐字不可变台词 <d>[Language] ...</d>。

overall_soundscape:
现场物理碰撞 Foley 音效、环境背景声（暴雨、蒸汽、金属轰鸣、喘息）。

non_diegetic_music:
SILENT
```

## 5. 生成前硬门禁（Gate Checks）

只有同时满足下列全部条件，才输出 `ready_for_prompt` 并允许提交生成：

- [ ] 叙事钩子、目标、阻力与权力转折可观察
- [ ] 所有 Cxx/Sxx/Pxx 资产存在、版本一致且已通过人工审核入库（`asset_registry.json`）
- [ ] **【声线门禁】** 出场说话角色的专属 WAV 声线文件已在本地就绪，且在提示词中正确指派 `<Audio N>`
- [ ] **【台词门禁】** 台词 100% 逐字匹配剧本不可变台账，口型可见性已通过校验（面部可见或声明画外）
- [ ] **【配乐门禁】** `non_diegetic_music` 严格锁定为 `SILENT`，无生成模型自造背景音乐
- [ ] 调度图锁定 180° 轴线，摄影机与角色世界坐标一致，绝不跳轴
- [ ] 布光能在画内找到物理光源依据
- [ ] 打戏/接触动作符合五阶段动作账本，包含 Anti-Bounce 物理约束
- [ ] 串行接力已锁定上一段 `-0.35s` 稳定尾帧为 `<Picture 1>`

任何一项不达标，必须退回对应设计层修复，严禁用无意义的重复抽卡掩盖错误。
